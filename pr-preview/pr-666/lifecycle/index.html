    1. App lifecycle

    The App lifecycle

    How humus.App reads its settings, builds its dependencies, runs its Services, shuts them down within a grace period and turns the outcome into an exit status.

    Every humus application is a bedrock.App, and the root package’s humus.App is the lifecycle every humus app type is built on. It reads its settings, listens for signals, builds the user’s dependencies, runs one or more Services, shuts them down within a grace period, releases what was built, and turns the outcome into an exit status.

    Most applications will not use humus.App directly. Each runtime package — REST, gRPC, jobs, queues — provides an App of its own, built on humus.App with that package’s defaults, and that is the API most users touch. Using humus.App directly, for example to run a REST API and a gRPC service in one process, is the advanced path. Read this page before taking it; read it, too, to understand what the App a runtime package builds for you does.

    Telemetry and health are not part of the lifecycle. Each is added by its own package, which integrates itself with the lifecycle as it lands:

    • telemetry by Proposal: OpenTelemetry without globals;
    • health by Proposal: health monitors and probes.

    Until they land, the lifecycle writes every failure to the process’s standard error.

    The design behind everything on this page is in Proposal: the humus App lifecycle.

    App

    An App has four fields:

    FieldRequiredMeaning
    Hostyesthe network and filesystem the App runs on: humus.OSHost() in main, and a Host the test controls in a test
    ShutdownGracePeriodyes, unless HUMUS_SHUTDOWN_GRACE_PERIOD is setthe grace period when HUMUS_SHUTDOWN_GRACE_PERIOD is not set. It must be positive, so the zero value fails startup
    DrainDelaynothe drain delay when HUMUS_SHUTDOWN_DRAIN_DELAY is not set: the pause between shutdown starting and Shutdown being called on the Services. It must not be negative; zero means no pause
    Inityesbuilds the App’s dependencies and returns the Services to run

    Its main is one call to bedrock.Main, the only place a humus program touches the real process:

    bedrock.Main(humus.App{
	Host:                humus.OSHost(),
	ShutdownGracePeriod: 30 * time.Second, // when HUMUS_SHUTDOWN_GRACE_PERIOD is not set
	DrainDelay:          5 * time.Second,  // when HUMUS_SHUTDOWN_DRAIN_DELAY is not set
	Init:                Init,
})

    ShutdownGracePeriod and DrainDelay are defaults: an operator overrides either through its variable without a rebuild. humus has no default grace period of its own, so an App sets ShutdownGracePeriod unless its environment always sets the variable; a DrainDelay left at zero means no pause. How long to pause and how long to allow for shutdown depend on the kind of App — a REST or gRPC App needs time for a load balancer to stop sending it connections, and a job does not — so each runtime package’s App sets its own.

    Service

    A Service is a long-running part of an App: an HTTP server, a gRPC server, a queue consumer or a job. It has two methods, Serve and Shutdown, and the App gives it two shutdown signals, at different times:

    1. Serve’s context is done as soon as the App starts shutting down, before the drain delay.
    2. Shutdown is called after the drain delay, with the grace period as its context’s deadline.

    A Service may stop on the first, as a job or a queue consumer does. Or it may keep serving until the second, as an HTTP, gRPC or health Service does, so that a load balancer still draining connections towards it is answered. This Service keeps serving until Shutdown:

    type server struct {
	out     io.Writer
	ready   chan struct{}
	stopped chan struct{}
}

func newServer(out io.Writer) *server {
	return &server{
		out:     out,
		ready:   make(chan struct{}),
		stopped: make(chan struct{}),
	}
}

func (s *server) Serve(ctx context.Context) error {
	_, err := fmt.Fprintln(s.out, "serve: serving")
	close(s.ready)
	if err != nil {
		return err
	}
	<-s.stopped
	return nil
}

func (s *server) Shutdown(ctx context.Context) error {
	close(s.stopped)
	_, err := fmt.Fprintln(s.out, "shutdown: stopped serving")
	return err
}

    Closing ready tells the example that runs it when it is serving. Serve returns nil when Shutdown stopped it or when it finished on its own. Any Service returning from Serve ends the App, so a job is just a Service that returns, and an App is never partly up. Shutdown is called on every Service, including one whose Serve has already returned, so it must be safe to call then. If its context is done before the Service has stopped, Shutdown stops it at once and returns an error that wraps the context’s error.

    Host

    A Host is what humus hands an App beyond its process: Listen, Dial and a filesystem, FS. Every field is required. In main an App runs on humus.OSHost(), which is net.Listen, a net.Dialer’s DialContext, and an FS that calls package os directly. In a test it runs on a Host whose listeners, dialler and filesystem the test controls, so that a whole App runs without touching the real host.

    Host is meant for user code as well as for humus. Hand Host.Dial to a client that takes a dial function, such as pgx’s DialFunc, and open files through Host.FS rather than through package os.

    Why FS hands out *os.File

    FS names files by OS path and opens them as *os.File, rather than through an in-memory filesystem:

    • Libraries that need a real file or a path keep working in a test: SQLite drivers, archive libraries, programs started with os/exec.
    • There is no fake filesystem to build and keep in line with the real one.
    • It is a one-way decision. An *os.File is always an OS handle, so moving to an in-memory filesystem later would change every signature.

    OSHost’s FS is not os.OpenRoot("/"), because an os.Root refuses to follow absolute symbolic links even when it is rooted at /, and paths on a real host routinely pass through them.

    What it costs a test: the rule is that it opens no file outside its own temporary directory; it cannot make a write fail with a full disk, so code that needs that test puts an io.Writer seam in its own code; and file modification times are real under synctest, so code that compares ModTime() with time.Now() needs Chtimes in its tests.

    Setup and OnStop

    Init is given a *humus.Setup holding the bedrock.Process the App is run with and the App’s Host. Init reads its configuration from Setup.Process, builds its dependencies on Setup.Host, and returns the Services to run. Its context is done when the App receives an interrupt or SIGTERM, so a slow Init, such as one retrying a database connection, is cancelled by a signal.

    Setup.OnStop registers a function that releases something Init built. The functions work like t.Cleanup: they run in reverse order of registration once every Service has stopped, and they run when Init fails partway through too. So register each release as soon as the thing it releases is built:

    func Init(ctx context.Context, s *humus.Setup) ([]humus.Service, error) {
	out := s.Process.Stdout
	s.OnStop(func(context.Context) error {
		_, err := fmt.Fprintln(out, "on stop: close the cache")
		return err
	})
	s.OnStop(func(context.Context) error {
		_, err := fmt.Fprintln(out, "on stop: close the queue")
		return err
	})

	if _, err := config.Env(s.Process.Environment, "DATABASE_URL").Read(ctx); err != nil {
		return nil, err // exit 78: init: config DATABASE_URL: not found
	}
	return []humus.Service{newServer(out)}, nil
}

    Run without DATABASE_URL, this App writes init: config DATABASE_URL: not found to standard error, closes the queue and then the cache, and exits 78.

    The OnStop functions share the grace period with the Services’ Shutdown: the context each is given is done when the grace period runs out.

    What Run does, in order

    1. Reads the lifecycle’s settings from the process’s environment, defaulting each to its App field. A malformed one, or a bad default, exits 78 before the App listens for signals, and Init is never called.
    2. Listens for an interrupt and SIGTERM through the process’s NotifyContext, before Init, so a signal during a slow Init cancels it.
    3. Calls Init. If it fails, runs the OnStop functions registered so far, within the grace period, and exits 78 when a *config.Error is in Init’s error chain, or 1 otherwise.
    4. Calls Serve on every Service concurrently.
    5. Waits for a signal, or for the first Service to return.
    6. Stops listening for signals, so that a second interrupt or SIGTERM takes its default action and ends the process at once, and cancels the context passed to Serve.
    7. Waits the drain delay: HUMUS_SHUTDOWN_DRAIN_DELAY, defaulting to App.DrainDelay.
    8. Calls Shutdown on every Service concurrently, waits for every Serve to return, and then runs the OnStop functions in reverse order of registration. All of this happens within one grace period, HUMUS_SHUTDOWN_GRACE_PERIOD, which starts after the drain delay.
    9. Returns the exit status.

    An Init that returns no Services ends the App at once, without a drain delay, as there is nothing to drain. A cancelled root context still gets a graceful shutdown: the grace period keeps the context’s values but not its cancellation. Every failure is the cause of the exit status and is written to standard error, one line per error; nothing else is written. The lifecycle never recovers a panic.

    Settings

    VariableDefaultMeaning
    HUMUS_SHUTDOWN_GRACE_PERIODApp.ShutdownGracePeriodbounds the whole shutdown: every Service’s Shutdown and every OnStop function share it. A time.ParseDuration string, such as 30s, that must be positive.
    HUMUS_SHUTDOWN_DRAIN_DELAYApp.DrainDelaythe pause between shutdown starting and Shutdown being called on the Services. A time.ParseDuration string, such as 5s, that must not be negative; 0s means no pause.

    These are the only variables the lifecycle reads, and the root package is the one place humus reads them. Each value is checked after its default, so a bad default fails the same way as a bad variable: an App whose ShutdownGracePeriod is zero, run without HUMUS_SHUTDOWN_GRACE_PERIOD, exits 78 with config HUMUS_SHUTDOWN_GRACE_PERIOD: must be positive. When both values are bad, both are reported, one line each.

    Exit codes

    CodeWhenCause
    0a signal stopped the App and it shut down in timethe signal
    0a Service returned nil on its own, and the App shut down in timenone
    1 (humus.ExitFailure)Init, a Service, a Service’s Shutdown or an OnStop function failedevery error, joined
    1 (humus.ExitFailure)the shutdown ran past the grace perioda *humus.GracePeriodError
    2never set by humus: Go’s exit status for an unrecovered panic
    78 (humus.ExitConfig)a setting is missing or malformed, including a config value read by Inita *config.Error in the chain

    78 is EX_CONFIG from sysexits.h. It tells an operator “fix the configuration” apart from “the service failed”. Everything else that fails exits 1, and a test tells those failures apart by their cause: errors.AsType[*config.Error] for a config error, and errors.AsType[*humus.GracePeriodError] for a shutdown that ran out of time. A flag usage error is an Init failure and exits 1.

    Testing a whole App

    An App runs whole inside a test. bedrocktest hands it a fake process, whose arguments and environment the test sets, whose output the test reads, and to which the test sends fake signals; and testing/synctest runs it in fake time, so a five-second drain delay passes at once and is measured exactly. The lifecycle’s own tests run it with fake Services:

    type fakeService struct {
	serve    func(ctx context.Context) error
	shutdown func(ctx context.Context) error

	mu            sync.Mutex
	shutdownCalls int
}

func (s *fakeService) Serve(ctx context.Context) error {
	if s.serve == nil {
		<-ctx.Done()
		return nil
	}
	return s.serve(ctx)
}

func (s *fakeService) Shutdown(ctx context.Context) error {
	s.mu.Lock()
	s.shutdownCalls++
	s.mu.Unlock()
	if s.shutdown == nil {
		return nil
	}
	return s.shutdown(ctx)
}

    This test runs an App with an HTTP-like Service and a consumer through a whole lifecycle, from SIGTERM to the OnStop functions:

    func TestApp_Run_a_whole_App(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		// api keeps serving until Shutdown, as an HTTP server does.
		stopped := make(chan struct{})
		var shutdownAt time.Time
		api := &fakeService{
			serve: func(context.Context) error {
				<-stopped
				return nil
			},
			shutdown: func(context.Context) error {
				shutdownAt = time.Now()
				close(stopped)
				return nil
			},
		}

		// consumer stops as soon as Serve's context is done, as a queue
		// consumer does.
		var consumerStoppedAt time.Time
		consumer := &fakeService{serve: func(ctx context.Context) error {
			<-ctx.Done()
			consumerStoppedAt = time.Now()
			return nil
		}}

		var poolClosedAt time.Time
		app := humus.App{
			Host:                humus.OSHost(), // the fake Services never use it
			ShutdownGracePeriod: 10 * time.Second,
			DrainDelay:          5 * time.Second,
			Init: func(_ context.Context, s *humus.Setup) ([]humus.Service, error) {
				s.OnStop(func(context.Context) error {
					poolClosedAt = time.Now()
					return nil
				})
				return []humus.Service{api, consumer}, nil
			},
		}

		p := bedrocktest.NewProcess(t)
		status := make(chan bedrock.ExitStatus, 1)
		go func() { status <- app.Run(t.Context(), p.Process()) }()

		<-p.Notified(syscall.SIGTERM)
		sigterm := time.Now()
		p.Signal(syscall.SIGTERM)
		st := <-status

		if st.Code() != 0 {
			t.Errorf("code = %d, want 0: %v", st.Code(), st.Cause())
		}
		if !errors.Is(st.Cause(), context.Canceled) {
			t.Errorf("cause = %v, want the signal", st.Cause())
		}
		if got := consumerStoppedAt.Sub(sigterm); got != 0 {
			t.Errorf("consumer stopped %s after SIGTERM, want at once", got)
		}
		if got := shutdownAt.Sub(sigterm); got != 5*time.Second {
			t.Errorf("Shutdown called %s after SIGTERM, want after the 5s drain delay", got)
		}
		if api.calls() != 1 || consumer.calls() != 1 {
			t.Errorf("Shutdown called %d and %d times, want once each", api.calls(), consumer.calls())
		}
		if poolClosedAt.IsZero() || poolClosedAt.Before(shutdownAt) {
			t.Errorf("OnStop ran at %v, want it after Shutdown at %v", poolClosedAt, shutdownAt)
		}
		if got := p.Stderr(); got != "" {
			t.Errorf("stderr = %q, want nothing", got)
		}
	})
}

    synctest reports a deadlock when a goroutine the App started outlives the test body, which makes it a leak detector for Services. For an HTTP Service the cost is that handlers must honour r.Context(), because a handler that ignores it after the server force-closes the connection outlives the test.

    Testing a humus App runs Apps that serve real HTTP, on a humustest Host whose network and filesystem the test controls.

    Ambient leaks

    Some dependencies read the real process behind an App’s back, so they reach around the bedrock.Process and the Host an App is given, and a test can neither control nor see what they read. Avoid them, or configure them explicitly from Setup:

    • pgx reads the real process. pgx.ParseConfig and pgxpool.ParseConfig take every setting the connection string leaves out from PGHOST, PGUSER, PGPASSWORD and the other PG* variables of the real environment, and default the user to the OS user. They read the password file that PGPASSFILE names, or ~/.pgpass, from the real disk and use it when the connection string sets no password, and they pick up client certificates from ~/.postgresql. The config they return dials the real network: set cfg.ConnConfig.DialFunc = s.Host.Dial before opening the pool. Its LookupFunc still resolves host names with the real resolver.
    • flag.CommandLine and flag.ExitOnError read os.Args and exit the process. Parse p.Args[1:] with a flag.FlagSet of your own, using flag.ContinueOnError.
    • An exec.Cmd with a nil Env inherits the real environment. Build its Env from the keys you know, reading each through p.Environment.
    • http.ProxyFromEnvironment, the Proxy of http.DefaultTransport, reads the proxy variables of the real environment, and http.DefaultClient dials the real network rather than through Host.Dial.
    • OpenTelemetry’s resource.Default reads the real environment, and its global providers are process-wide state.
    • slog.Default writes to the real standard error unless it is replaced, and replacing it is process-wide state.

    The last five are on bedrock’s own list. A dependency found reading the real process belongs on this list.
