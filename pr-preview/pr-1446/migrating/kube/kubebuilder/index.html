Migrating from kubebuilder

How to move a kubebuilder v4 operator to humus’s kube module, on client-go with no controller-runtime: what each kubebuilder and controller-runtime concept becomes, then its process, settings, telemetry, probes, leader election and shutdown on humus, its custom resource declared as Go values with its CRD kept by a golden test, its reconciler handed its object, its finalizer, its RBAC and its pod. One set of test cases passes against both operators.

This guide moves a small kubebuilder v4 operator to humus’s kube module. Its reconciler runs on client-go through humus, with no controller-runtime. Its process, settings, telemetry, probes, leader election and shutdown become humus’s. An operator built with operator-sdk’s Go plugin, which is built on kubebuilder, moves the same way.

kubebuilder generates the CRD and the RBAC from markers in comments, with controller-gen. humus declares the custom resource as Go values with typed constraints, keeps its CRD true to the types with a golden test, and leaves the RBAC to the end user. The guide’s steps go from the kubebuilder operator to the humus controller, rather than each leaving an operator that runs.

The kubebuilder operator

The guide’s code is under example/kube/kubebuilder, a module for each operator:

example/kube/kubebuilder/
├── cases/    the black-box test cases both operators pass
├── start/    the kubebuilder operator the guide starts from
└── humus/    the humus controller it ends with

The operator is the Memcached operator of kubebuilder’s tutorial, with the finalizer and the Event of its deploy-image plugin. A Memcached says how many memcached pods run. Its controller creates a Deployment of them, keeps the Deployment’s size, and reports it in the Memcached’s Available condition. Its types carry markers:

type MemcachedSpec struct {
	// size defines the number of Memcached instances
	// +kubebuilder:validation:Minimum=1
	// +kubebuilder:validation:Maximum=3
	// +optional
	Size *int32 `json:"size,omitempty"`
}

type MemcachedStatus struct {
	// conditions represent the current state of the Memcached resource.
	// +listType=map
	// +listMapKey=type
	// +optional
	Conditions []metav1.Condition `json:"conditions,omitempty"`
}

make generate writes zz_generated.deepcopy.go, and make manifests writes the CRD to config/crd/bases/ and the RBAC to config/rbac/role.yaml, both with controller-gen.

Reconcile is handed a name, so it fetches the Memcached first:

memcached := &cachev1alpha1.Memcached{}
err := r.Get(ctx, req.NamespacedName, memcached)
if err != nil {
	if apierrors.IsNotFound(err) {
		log.Info("Memcached resource not found, ignoring since object must be deleted")
		return ctrl.Result{}, nil
	}
	log.Error(err, "Failed to get memcached")
	return ctrl.Result{}, err
}

It sets the condition Unknown and fetches the Memcached again, adds the finalizer with an update, and creates the Deployment, or updates its size, and requeues after a minute. Once the Deployment has the size, it updates the status:

meta.SetStatusCondition(&memcached.Status.Conditions, metav1.Condition{Type: typeAvailableMemcached,
	Status: metav1.ConditionTrue, Reason: reasonReconciling,
	Message: fmt.Sprintf("Deployment for custom resource (%s) with %d replicas created successfully", memcached.Name, desiredReplicas)})

if err := r.Status().Update(ctx, memcached); err != nil {
	log.Error(err, "Failed to update Memcached status")
	return ctrl.Result{}, err
}

Once the Memcached is being deleted, it sets a Degraded condition, records an Event, sets the condition again and removes the finalizer:

func (r *MemcachedReconciler) doFinalizerOperationsForMemcached(cr *cachev1alpha1.Memcached) {
	r.Recorder.Eventf(cr, nil, corev1.EventTypeWarning, "Deleting", "DeleteCR",
		"Custom Resource %s is being deleted from the namespace %s",
		cr.Name,
		cr.Namespace)
}

It watches the Memcacheds and the Deployments they own:

func (r *MemcachedReconciler) SetupWithManager(mgr ctrl.Manager) error {
	return ctrl.NewControllerManagedBy(mgr).
		For(&cachev1alpha1.Memcached{}).
		Named("memcached").
		Owns(&appsv1.Deployment{}).
		Complete(r)
}

The cases module holds black-box cases, written once. Each creates a namespace of its own, and Memcacheds in it with the dynamic client, as a user of the CRD would, then waits for what the operator does:

One scales the Deployment by hand, and waits for the operator to put the Memcached’s size back:

func ScaledByHand(t testing.TB, target Target) {
	ctx := bounded(t, target)
	c := newCluster(ctx, t, target)

	c.create(ctx, t, "cache", 2)
	c.awaitAvailable(ctx, t, "cache", 2)

	deployments := c.kube.AppsV1().Deployments(c.namespace)
	scale, err := deployments.GetScale(ctx, "cache", metav1.GetOptions{})
	require.NoError(t, err)
	scale.Spec.Replicas = 1
	_, err = deployments.UpdateScale(ctx, "cache", &autoscalingv1.Scale{ObjectMeta: scale.ObjectMeta, Spec: scale.Spec}, metav1.UpdateOptions{})
	require.NoError(t, err)

	c.awaitReplicas(ctx, t, "cache", 2)
}

Deletion deletes a Memcached, and waits for the Event, for the Memcached to be gone and for its Deployment to be garbage collected.

Step 1: main and its settings

main becomes one call to humus.Main:

humus.Main(Init, humus.WithTelemetry(buildTelemetry))

Init builds the Client, the controller and its probes:

func Init(ctx context.Context, s *humus.Setup) ([]humus.Service, error) {
	settings, err := readSettings(ctx, s)
	if err != nil {
		return nil, err
	}

	client, err := kube.NewClient(s, settings.Connection)
	if err != nil {
		return nil, err
	}
	kc, err := kubernetes.NewForConfig(client.Config())
	if err != nil {
		return nil, err
	}

	r := controller.Reconciler{Kube: kc, Instance: settings.Controller.LeaderElection.Identity}
	ctrl, err := kube.NewController(s, client, settings.Controller, v1alpha1.Memcached, r,
		kube.Owns(appsv1.SchemeGroupVersion.WithResource("deployments")),
		kube.Finalize(memcachedFinalizer, r.Finalize),
	)
	if err != nil {
		return nil, err
	}
	probes, err := httphealth.NewService(s, settings.Probes, health.Readiness(ctrl.Synced()))
	if err != nil {
		return nil, err
	}
	return []humus.Service{ctrl, probes}, nil
}

readSettings sources the controller, the API server and the probes from the environment:

func readSettings(ctx context.Context, s *humus.Setup) (settings, error) {
	env := func(name string) config.Value[string] { return config.Env(s.Process.Environment, name) }

	return config.Struct(func(r *config.Resolver) settings {
		k := kube.DefaultSettings()
		k.Name = r.Get(env("CONTROLLER_NAME").Validate(kube.CheckName))
		k.LeaderElection.Namespace = r.Get(env("POD_NAMESPACE").Validate(kube.CheckNamespace))
		k.LeaderElection.Identity = r.Get(env("POD_NAME").Validate(kube.CheckIdentity))

		tokenFile := r.Get(env("KUBERNETES_TOKEN_FILE").Default(serviceAccount + "token"))
		return settings{
			Connection: kube.Connection{
				Server: net.JoinHostPort(r.Get(env("KUBERNETES_SERVICE_HOST")), r.Get(env("KUBERNETES_SERVICE_PORT"))),
				TLS:    r.Get(env("KUBERNETES_CA_FILE").Default(serviceAccount + "ca.crt").Parse(trusting(s.Host.FS)).Validate(kube.CheckTLS)),
				Token: func(context.Context) (string, error) {
					b, err := readFile(s.Host.FS, tokenFile)
					return string(bytes.TrimSpace(b)), err
				},
			},
			Controller: k,
			Probes: httphealth.Settings{
				Addr: r.Get(env("PROBES_ADDR").Validate(httphealth.CheckAddr)),
				TLS: r.Get(env("PROBES_TLS_CERT_FILE").FlatMap(func(certFile string) config.Value[*tls.Config] {
					return env("PROBES_TLS_KEY_FILE").Parse(serverTLS(s.Host.FS, certFile))
				}).Validate(httphealth.CheckTLS)),
			},
		}
	}).Read(ctx)
}

From here on, these are humus’s:

  • The process and its shutdown. On SIGTERM the controller stops taking Memcacheds, finishes the reconciles in flight, releases the Lease and exits 0, within a 20s grace period, as Leader election and shutdown describes. The Manager left its Lease to expire.
  • Leader election. It is always on, on a Lease named CONTROLLER_NAME in POD_NAMESPACE. CONTROLLER_NAME is the operator’s LeaderElectionID, so during the rollout the humus pods wait for the operator’s Lease, and the two never reconcile at once.
  • The settings. A missing or bad one makes the controller exit 78, naming its variable.
  • Telemetry. buildTelemetry names the service memcached-operator, as Writing the Builder shows. Each reconcile is a span, each API request a child span, and the controller’s instruments take the place of controller-runtime’s Prometheus metrics.
  • The probes. The kubelet probes /health/liveness and /health/readiness on PROBES_ADDR, with scheme: HTTPS. The pod is ready once the controller’s caches have synced.

Step 2: the custom resource

The types keep their fields and lose their markers. The constraints and the descriptions become kube.Rules:

type MemcachedSpec struct {
	Size int32 `json:"size,omitempty"`
}

type MemcachedStatus struct {
	Conditions []metav1.Condition `json:"conditions,omitempty"`
}

var (
	spec   MemcachedSpec
	status MemcachedStatus

	Memcached = kube.Resource[MemcachedSpec, MemcachedStatus]{
		Group:   "cache.example.com",
		Version: "v1alpha1",
		Kind:    "Memcached",
		Plural:  "memcacheds",
		Scope:   kube.Namespaced,
		Rules: []kube.TypeRules{
			kube.Rules(&spec,
				kube.Field(&spec.Size).Minimum(1).Maximum(3).Description("size defines the number of Memcached instances"),
			).Description("spec defines the desired state of Memcached"),
			kube.Rules(&status,
				kube.Field(&status.Conditions).ListMap("type").Description("conditions represent the current state of the Memcached resource."),
			).Description("status defines the observed state of Memcached"),
		},
	}
)

Size is an int32 with omitempty rather than a pointer: either is an optional integer in the schema, and a Memcached without one ends with a Deployment of no pods. The Memcached and MemcachedList structs, groupversion_info.go and zz_generated.deepcopy.go are gone, and with them the scheme.

A golden test takes the place of make manifests. It writes the CRD where controller-gen wrote it, so whatever applies the CRD keeps applying it:

func TestMemcachedCRD(t *testing.T) {
	crd, err := Memcached.CRD()
	require.NoError(t, err)
	got, err := yaml.Marshal(crd)
	require.NoError(t, err)

	const path = "../../config/crd/bases/cache.example.com_memcacheds.yaml"
	if *update {
		require.NoError(t, os.WriteFile(path, got, 0o644))
	}
	want, err := os.ReadFile(path)
	require.NoError(t, err)
	require.Equal(t, string(want), string(got))
}

go test ./api/... -update

The CRD it writes differs from the one controller-gen generated:

  • Descriptions. The spec, the status, size and conditions keep theirs. The object, apiVersion and kind have none, so kubectl explain shows less.
  • Each condition. controller-gen copies apimachinery’s markers on metav1.Condition: a description of each field, an enum of status, a pattern and a length for type and reason, a length for message and a minimum for observedGeneration. humus reflects the Go type, so each field has its type, the same five are required, and none is constrained. Only the controller writes conditions, with meta.SetStatusCondition.
  • The rest. The controller-gen.kubebuilder.io/version annotation is gone, and the file carries an empty status, which the API server ignores.

Both reject a size of 0 or 4, as the Validation case checks.

Step 3: the reconciler

The Reconciler is handed the Memcached. It applies the Deployment, and returns the condition the operator updated:

func (r Reconciler) Reconcile(ctx context.Context, m kube.Object[v1alpha1.MemcachedSpec, v1alpha1.MemcachedStatus]) (kube.Result[v1alpha1.MemcachedStatus], error) {
	st := m.Status
	_, err := r.Kube.AppsV1().Deployments(m.Namespace).Apply(ctx, deploymentForMemcached(m), metav1.ApplyOptions{FieldManager: controllerName, Force: true})
	if err != nil {
		meta.SetStatusCondition(&st.Conditions, metav1.Condition{Type: typeAvailableMemcached,
			Status: metav1.ConditionFalse, Reason: reasonReconciling,
			Message: fmt.Sprintf("Failed to apply the Deployment for the custom resource (%s): (%s)", m.Name, err)})
		return kube.Result[v1alpha1.MemcachedStatus]{Status: &st}, err
	}

	meta.SetStatusCondition(&st.Conditions, metav1.Condition{Type: typeAvailableMemcached,
		Status: metav1.ConditionTrue, Reason: reasonReconciling,
		Message: fmt.Sprintf("Deployment for custom resource (%s) with %d replicas created successfully", m.Name, m.Spec.Size)})
	return kube.Result[v1alpha1.MemcachedStatus]{Status: &st}, nil
}

There is no Get, no not found, no first Unknown condition, no Status().Update, no fetching again and no requeue. A change to the Deployment reconciles the Memcached through kube.Owns, as Owns did.

The Deployment is the operator’s, as client-go’s apply configurations, with the owner reference ctrl.SetControllerReference set:

func deploymentForMemcached(m kube.Object[v1alpha1.MemcachedSpec, v1alpha1.MemcachedStatus]) *appsv1ac.DeploymentApplyConfiguration {
	ls := labelsForMemcached(m.Name)
	return appsv1ac.Deployment(m.Name, m.Namespace).
		WithOwnerReferences(metav1ac.OwnerReference().
			WithAPIVersion(m.APIVersion).WithKind(m.Kind).WithName(m.Name).WithUID(m.UID).
			WithController(true).WithBlockOwnerDeletion(true)).
		WithSpec(appsv1ac.DeploymentSpec().
			WithReplicas(m.Spec.Size).
			WithSelector(metav1ac.LabelSelector().WithMatchLabels(ls)).
			WithTemplate(corev1ac.PodTemplateSpec().
				WithLabels(ls).
				WithSpec(corev1ac.PodSpec().WithContainers(corev1ac.Container().
					WithImage("memcached:1.6.26-alpine3.19").
					WithName(memcachedContainerName).
					WithPorts(corev1ac.ContainerPort().WithContainerPort(11211).WithName(memcachedContainerName)).
					WithCommand("memcached", "--memory-limit=64", "-o", "modern", "-v")))))
}

Its selector is the operator’s, and a Deployment’s selector can’t change, so the controller takes over the Deployments the operator created as they are. The apply is forced, so it puts back every field it declares, where the operator compared only the replicas.

kube.Finalize adds the finalizer before the first reconcile, calls its function once the Memcached is being deleted, and removes the finalizer once the function returns nil. humus has no event recorder, so the function creates the Event with the clientset, named as client-go names one:

func (r Reconciler) Finalize(ctx context.Context, m kube.Object[v1alpha1.MemcachedSpec, v1alpha1.MemcachedStatus]) error {
	now := time.Now()
	_, err := r.Kube.EventsV1().Events(m.Namespace).Create(ctx, &eventsv1.Event{
		ObjectMeta:          metav1.ObjectMeta{Name: fmt.Sprintf("%s.%x", m.Name, now.UnixNano())},
		EventTime:           metav1.NewMicroTime(now),
		ReportingController: controllerName,
		ReportingInstance:   r.Instance,
		Action:              "DeleteCR",
		Reason:              "Deleting",
		Type:                corev1.EventTypeWarning,
		Regarding: corev1.ObjectReference{
			APIVersion: m.APIVersion, Kind: m.Kind, Name: m.Name, Namespace: m.Namespace,
			UID: m.UID, ResourceVersion: m.ResourceVersion,
		},
		Note: fmt.Sprintf("Custom Resource %s is being deleted from the namespace %s", m.Name, m.Namespace),
	}, metav1.CreateOptions{})
	return err
}

An error retries the function, so a retry may record the Event twice. A Finalize’s function returns no status, so the Degraded condition is gone.

The leader election Role kubebuilder scaffolds keeps only the Lease’s verbs:

Step 5: the pod

config/manager/manager.yaml sets variables in place of the flags. The Lease’s namespace and identity come from the downward API:

env:
- name: CONTROLLER_NAME
  value: 4b13e8ac.example.com
- name: POD_NAMESPACE
  valueFrom:
    fieldRef:
      fieldPath: metadata.namespace
- name: POD_NAME
  valueFrom:
    fieldRef:
      fieldPath: metadata.name
- name: PROBES_ADDR
  value: :8081
- name: PROBES_TLS_CERT_FILE
  value: /etc/manager/probes/tls.crt
- name: PROBES_TLS_KEY_FILE
  value: /etc/manager/probes/tls.key

The probes move to humus’s paths, over HTTPS:

livenessProbe:
  httpGet:
    path: /health/liveness
    port: probes
    scheme: HTTPS
  initialDelaySeconds: 15
  periodSeconds: 20
readinessProbe:
  httpGet:
    path: /health/readiness
    port: probes
    scheme: HTTPS
  initialDelaySeconds: 5
  periodSeconds: 10

The probes’ certificate is the Secret controller-manager-probes, of the end user’s own: the kubelet doesn’t verify it. terminationGracePeriodSeconds goes from kubebuilder’s 10 to 30, which holds humus’s 20s grace period. The metrics port, and the Service and the ServiceMonitor kubebuilder scaffolds for it, are gone: the metrics leave with OTLP.

Step 6: test it

The cases run against the whole humus controller, with humustest.Start and humus.OSHost(), against k3s:

p, status := humustest.Start(t, Init,
	humustest.WithApp(humus.WithHost(humus.OSHost()), humus.WithTelemetry(telemetry.NoopBuilder)),
	humustest.WithEnv(map[string]string{
		"KUBERNETES_SERVICE_HOST": server.Hostname(),
		"KUBERNETES_SERVICE_PORT": server.Port(),
		"KUBERNETES_CA_FILE":      writeFile(t, dir, "ca.crt", caData),

		"CONTROLLER_NAME":         controllerName,
		"POD_NAMESPACE":           controllerNamespace,
		"POD_NAME":                "controller-manager-0",
		"PROBES_ADDR":             probesAddr,
		"PROBES_TLS_CERT_FILE":    writeFile(t, dir, "tls.crt", certPEM),
		"PROBES_TLS_KEY_FILE":     writeFile(t, dir, "tls.key", keyPEM),
	}),
)

Once the cases pass, the test checks that the controller holds the Lease, sends SIGTERM, and checks that it exits 0 and releases the Lease. The Reconciler is tested as a function, on client-go’s fakes, and Init’s settings inside synctest, as Testing describes. In place of envtest’s kube-apiserver and etcd, the whole controller runs against k3s. The module’s go.mod requires no controller-runtime.

What clients see change:

  • The status never shows the Available condition Unknown before the first reconcile, nor a Degraded condition while the Memcached is being deleted.
  • A hand-made change to the Deployment is undone for every field the controller declares, not only the replicas.
  • The CRD has fewer descriptions, and no constraints on its conditions.
  • The Deleting Event names the pod as its reportingInstance, where client-go named the controller and the host.
  • The probes answer on /health/liveness and /health/readiness, over HTTPS.
  • The metrics leave with OTLP, rather than waiting for Prometheus on :8443.
